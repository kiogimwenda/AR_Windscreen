Appendix B: Host–Hub Protocol Reference

Frame: 0xAA | type (1) | length (2, LE) | payload (length) | CRC (2, LE). The CRC is CRC-16/CCITT-FALSE (polynomial 0x1021, initial value 0xFFFF, no reflection, no final XOR; check value 0x29B1 for “123456789”), computed over type, length and payload. All multi-byte fields are little-endian and packed; payload sizes are asserted at compile time on both the hub and the host.

Watchdog contract. The hub treats the link as lost when no valid frame has arrived for 200 ms. A command that requests an action is accepted only while the hub is armed and only if its host timestamp is newer than the last accepted one, so a stale or replayed frame never acts; a command requesting nothing is always accepted, since it can only release. A brake always ends after its own duration or 1.5 s, whichever is shorter; heartbeats do not extend it.

Appendix C: Safety Properties and Fault Codes

The finished system must demonstrate five non-negotiable properties, each verified explicitly:

  1. The driver’s foot always overrides the actuator (pull-only cable; bench check 3).
  2. A physical kill switch removes actuator power independent of software (E-stop in the relay coil loop; bench check 4).
  3. The hub releases the actuator within 200 ms of host link loss, independent of host software (watchdog task, IWDG backstop; bench check 5). Across the two-box split, the power board releases in hardware whenever the pod is not driving it (bench check 6).
  4. The host never drives actuation hardware directly; it only sends a bounded request, and the hub enforces the real ceiling.
  5. Every actuation event (request, hub decision, applied intensity and duration, release reason) is logged with a timestamp on both host and hub.

Appendix D: Key Algorithms

{{fig:fig_software_dataflow.svg|Host software dataflow; each arrow is a typed message on a ring buffer}} {{fig:fig_frame_pipeline.svg|Per-frame perception and fusion flow}} {{fig:fig_navigation.svg|Navigation pipeline and the three road-status layers|4.3}}

D.1 Decision arbiter, rule 1 (brake)

for each confirmed track o in the ego path, ahead of the bumper: if o.range was measured by LiDAR within 200 ms and o.closingSpeed > 0.5 m/s and all values finite: ttc(o) = o.gap / o.closingSpeed target = argmin ttc armed = hubReportAge ≤ 100 ms and killSwitch released and no actuator fault and eventLog healthy if target exists and ttc(target) < 1.8 s and pedal not pressed and armed: intensity = min(configured 60, configured max 90, hub ceiling 90) log(rule 1, ttc, gap, closing speed, target, armed) # before sending send BRAKE(intensity)

D.2 Mask-based fusion, per object

for each LiDAR point p (time t_p): q = compensate(p, t_p → t_camera, ego speed, yaw rate) drop q if |ground.distance(q)| < 0.15 m (u, v) = project(q) # pinhole + k1 k2 p1 p2 k3 distortion keep only the nearest point in each 4 px cell # depth test for each detection d: P = visible points inside erode(mask(d), 1 cell) clusters = split P by depth at gaps > 0.5 m c = nearest cluster with ≥ 20% of P if |c| ≥ 3: range(d) = median(c), source = LIDAR else: range(d) = MiDaS estimate scaled by LiDAR objects, source = ESTIMATED non-ground corridor points claimed by no mask → UNKNOWN obstacles

D.3 Hub watchdog task (every 20 ms)

kick IWDG (500 ms) if now - lastValidHostFrame > 200 ms or report loop silent > 200 ms or killSense pressed or frameErrors > 10/50: release actuator directly (PWM 0, enables low, magnet off) # no mutex relays off; forget last command; state = DISARMED

D.4 HMM map matching

For fix zt and candidate road point xt, emission p(zt|xt) ∝ exp(−½(|zt − xt|/σ)2); transition p(xt|xt−1) ∝ exp(−|droute − dstraight|/β), where droute is the driving distance between candidates and dstraight the distance between fixes; the Viterbi path over a sliding window gives the matched positions {{cite:newson2009}}.

Appendix E: Test Plan and Checklists

Stage A: actuator bench rig (gate)

  • Rig check: actuator and pedal fixture on the bench, not in a vehicle.
  • Intensity sweep: applied intensity, current, force and response time logged per step.
  • Push-back: a person moves the pedal by foot at maximum configured intensity.
  • Kill switch pressed mid-actuation: drive and current fall to zero; actuator goes limp.
  • USB unplugged mid-actuation: release and zero current within 200 ms, measured by the hub.
  • Inter-box cable pulled mid-actuation: limp at once; fault 5 reported; no false overcurrent latch.
  • Exit: all six pass on three consecutive attempts, and again on the custom PCB hardware.

Stage B: stationary in vehicle (handbrake on, wheels chocked)

  • SensorReports show real OBD-II (read over CAN), GNSS and IMU data.
  • IMU mount and camera pitch calibrated; the knock check reads under 1°.
  • Inter-box cable pulled with the actuator applied: releases, fault 5.
  • A person walking into view at close range produces the correct request in the event log.
  • The actuator engages and the driver can push through it, as on the bench.
  • Kill switch and watchdog checks repeated in the vehicle.
  • Road-projection check performed on first movement.

Stage C: empty field, spotter present

  • Actuation, override and watchdog behaviour hold at low vehicle speed.
  • Recorded explicitly: stopping-distance and TTC calibration are not validated on loose ground.

Stage D: closed campus road section

  • Formal closure arranged with campus security; department safety notification filed in advance.
  • Near-zero foot traffic; spotters at both ends and one alongside; agreed abort signal.
  • Speed capped at 5–10 km/h.
  • First runs with a manual confirm-to-brake step before automatic triggering.
  • Full event log retained from every run.
